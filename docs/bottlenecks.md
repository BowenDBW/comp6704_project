## 一、各类方法的 Bottleneck

### 1. 单纯形类方法（Simplex Family）

| # | Bottleneck | 说明 | 文献依据 |
|---|---|---|---|
| 1.1 | **最坏情况指数复杂度** | Klee–Minty 构造使单纯形迭代次数指数增长；实践中快但缺理论保证，smoothed analysis 是目前最好的解释 | `1504.08251` |
| 1.2 | **退化性（degeneracy）导致迭代停滞** | 运输问题的 LP 是高度退化的典型（总供给=总需求时约束秩亏 1，基解大量重合），造成基交换暴增、循环风险，需要 Bland 规则/扰动法等防护，代价是收敛变慢 | `2203.02795` |
| 1.3 | **本质串行，难以并行** | 基反转（basis update）必须按序执行；并行化只能加速定价（pricing）和比值检验（ratio test）等子步骤，整体加速比有限 | `1503.01889` |
| 1.4 | **大规模问题的基操作开销** | 修止单纯形依赖基矩阵的稠密/稀疏分解，问题规模增大时定价与更新成本主导运行时间 | `1503.01889`、`huangfu2018highs`(HiGHS) |

### 2. 内点法（Interior-Point Methods）

| # | Bottleneck | 说明 | 文献依据 |
|---|---|---|---|
| 2.1 | **每次迭代的牛顿方程组求解主导开销** | 需对大规模稀疏对称矩阵做 Cholesky 分解，内存与计算随规模增长快，且稀疏分解的填充模式难以并行/GPU 化——这是 IPM 与一阶方法拉开规模差距的根源 | `1805.12344`、`rothberg2026hybrid` |
| 2.2 | **中心路径末端的病态性** | 逼近最优时 μ→0，牛顿系统条件数爆炸，数值误差放大；需正则化（regularization）或非精确求解技巧维持稳定 | `2105.01333` |
| 2.3 | **解是内部点而非顶点解** | 物流场景需要"哪些线路被启用"的基结构解释和影子价格；IPM 输出需 crossover 步骤转回顶点解，额外开销且可能引入数值问题 | `2203.02795`（基解/稳定性视角） |
| 2.4 | **多项式复杂度 ≠ 实际可扩展** | 迭代次数少（几十次），但单次迭代代价高，在千万级变量的实例上被一阶方法超越 | `applegate2025pdlp` |

### 3. 一阶方法与 GPU 求解器（PDHG/PDLP 系列）⭐ 近年最热

| # | Bottleneck | 说明 | 文献依据 |
|---|---|---|---|
| 3.1 | **精度天花板** | 只能达到中等精度（相对误差 ~1e-4 至 1e-6），无法到机器精度；供应链规划等需要精确对账/整数可读方案的场景是硬伤 | `applegate2025pdlp`、`lu2025cupdlpx` |
| 3.2 | **尾部收敛慢** | 误差下降到中等水平后收敛骤缓，依赖重启（restart）启发式维持实用速度 | `applegate2025pdlp` |
| 3.3 | **对缩放/病态高度敏感** | 原始-对偶步长和收敛性受问题缩放影响大，需要预条件（preconditioning）、缩放（scaling）、presolve 等工程手段兜底 | `lu2025cupdlpx`、`cederberg2026presolve` |
| 3.4 | **参数调优本身成为研究问题** | 步长/重启策略的选择影响巨大，自动调优需要泛化保证，否则换一批实例就失效 | `prasad2026tuning`、`sul2026rl` |
| 3.5 | **无基结构/影子价格弱** | 不产生对偶基分解，灵敏度分析（如某仓库扩容的边际收益）解释力不如单纯形 | `applegate2025pdlp`（讨论部分） |

### 4. 结构利用与分解方法（Network Simplex / 列生成 / Benders）

| # | Bottleneck | 说明 | 文献依据 |
|---|---|---|---|
| 4.1 | **适用范围受限** | 网络单纯形只对纯网络流 LP 有效；加入固定费用、共享容量、非线性成本即失效，需回退通用方法 | `holzhauser2016network`、`saraswathi2026support` |
| 4.2 | **列生成 tailing-off** | 主问题迭代后期每步改进微小，收敛慢；定价子问题（pricing subproblem）本身可能成为计算瓶颈 | `guan2026supplychain` |
| 4.3 | **多商品流的规模爆炸** | node-arc 公式化下变量数随商品数线性增长，单体 LP 直接不可解，必须分解——而分解又引入 4.2 | `dai2019mcf`、`brand2023mcf` |

### 5. 学习增强优化（Learning-Augmented）

| # | Bottleneck | 说明 | 文献依据 |
|---|---|---|---|
| 5.1 | **泛化性无保证** | 在训练分布外的实例上加速效果不保证，可能反而拖慢 | `prasad2026tuning` |
| 5.2 | **只能加速不能替代** | 学习组件不改变精确性保证的角色定位，只做启发式加速器；精确解仍靠传统方法兜底 | `sul2026rl` |

## 二、跨方法的核心矛盾（报告 "gap" 叙事）

```
            精确性（顶点解/影子价格）
                 ▲
                 │  Simplex          IPM
                 │  （串行、退化敏感）  （迭代内分解、难并行）
                 │
                 │         ← 混合化（PDHG+IPM, ADMM-IPM）
                 │         ← 学习加速（RL 调参）
                 │
                 │       一阶方法/GPU（PDLP 系列）
                 │
                 └──────────────────────────────▶ 规模 & 并行性
```

1. **精度 vs 规模 vs 并行性三者不可兼得**：单纯形/IPM 精确但受限于分解式线性代数；一阶方法可并行、可扩展但精度有限且尾部收敛慢。最新趋势是**混合化**（`2603.03150` PDHG+IPM、`1805.12344` ADMM+IPM）与**学习加速**（`2610.01546`）。
2. **通用性 vs 结构利用**：网络结构利用类算法在纯网络 LP 上快一个量级，但一旦加侧约束/固定费用就失效（`1607.02284`、`2609.09295`）。
3. **退化性是所有顶点遍历方法的共同压力源**：运输 polytope 是高度退化 LP 的典型代表（`2203.02795`），使运输问题成为天然的方法压力测试基准。

## 三、对本课程项目实验设计的启示

| Bottleneck | 可设计的实验 |
|---|---|
| 1.2 退化性 | 构造供给=需求的均衡实例 vs 非均衡实例，对比单纯形迭代次数退化程度（sensitivity analysis，直接呼应 rubric 的 "ablation/sensitivity"） |
| 1.3/2.1 串行 vs 分解开销 | 对比单纯形与 IPM 在不同问题规模（m×n 网格）下的运行时间伸缩曲线（convergence rate + computational efficiency） |
| 3.1 精度 | 以 HiGHS 机器精度解为基准，统计各算法达到 1e-6/1e-4 解所需时间（solution quality 指标） |
| 4.1 网络结构 | 网络单纯形 vs 通用单纯形在同一运输实例上的加速比（highlight "distinctive characteristics of each algorithm"） |
| 2.3 顶点解 | 对比 IPM（内点）与单纯形（顶点解）的解结构差异：启用线路数、影子价格一致性（duality gap） |

> 分工对应：成员 A（原始单纯形）主攻 1.1/1.2；B（对偶单纯形）主攻 1.3；C（内点法）主攻 2.2/2.3；D（网络单纯形）主攻 4.1。每人负责实现一个算法（满足课程 "each member independently implement at least one algorithm" 要求），并在报告中分别论证上述 bottleneck。
